# 潮汐 · 外部设备对接指南

> 用于让**其他电脑 / 手机 / 第三方程序**读写潮汐工作台的数据。
> 服务端：`https://2566.online/workboard`（自有服务器，数据唯一落点）。

---

## 一、两种对接方式，先选对

| 方式 | 适合 | 凭据 | 能做什么 |
|---|---|---|---|
| **A. 网页登录** | 人在别的电脑/手机上手动记、看 | 登录密码 | 全部功能（读写所有页、Agent 对话、建技能） |
| **B. APP Key（API）** | 程序/脚本/快捷指令自动写入 | `X-API-Key` | 读 8 张表 + 新增记录（只读 Key 不能写） |

**只是想换台电脑继续用工作台 → 用 A，打开网址输密码即可，不用 Key。**
**想让脚本、快捷指令、其他 AI 自动往里写 → 用 B，按下面走。**

---

## 二、方式 A：网页登录（最省事）

1. 浏览器打开 `https://2566.online/workboard/`
2. 输入登录密码
3. 登录后即可读写全部数据，与本机体验一致

> 无需安装、无需配置 Key。手机浏览器同样可用。
> 证书有效至 2027-02-19，且已配自动续期。

---

## 三、方式 B：APP Key 对接（程序写入）

### 1. 拿到 Key

登录网页 → 左侧「APP Key」页 → 生成 Key（选 read 只读 / write 可写，填用途备注）。

- **明文只在生成那一刻显示一次**，立刻复制保存；服务端只存哈希，丢了无法找回，只能吊销重建。
- 写入必须用 `write` 权限的 Key；`read` Key 写入会返回 403。

### 2. 接口地址

Base URL：`https://2566.online/workboard/api/external/v1`

```
GET  /api/external/v1/{表}          # 读列表
POST /api/external/v1/{表}          # 新增一条（需 write Key）
```

表名白名单（`{表}` 只能取这些值）：

| 表 | 说明 |
|---|---|
| `task` | 任务 |
| `time` | 时间记录 |
| `inbox` | 收集箱（想法/问题/待定）|
| `review` | 每日复盘 |
| `week` | 周计划 |
| `milestone` | 阶段 |
| `log` | 留痕 |
| `subtask` | 子任务 |

### 3. 鉴权

请求头加：

```
X-API-Key: <你的Key>
Content-Type: application/json
```

### 4. 写入示例（记一条任务）

```bash
curl -X POST "https://2566.online/workboard/api/external/v1/task" \
  -H "X-API-Key: 你的Key" \
  -H "Content-Type: application/json" \
  -d '{"任务名称":"整理季度复盘材料","状态":"待办","优先级":"P0","计划日":"2026-11-23T00:00:00Z"}'
```

返回：

```json
{"record_id":"xxxxxxxx","任务名称":"整理季度复盘材料", ...}
```

### 5. 各表常用字段

**task（任务）**
`任务名称` · `状态`（待办/进行中/已完成）· `优先级`（P0/P1/P2）· `到期日` · `计划日` · `备注` · `来源`（手动/顺延/复盘生成/导入）· `事项类型`（深度思考/独立专注/复杂协作/简单协作/灵感闪现）· `时段` · `负责人` · `事项二`

**time（时间记录）**
`日期` · `事项` · `时长`（分钟）· `分类` · `开始时间` · `结束时间` · `使用类型`

**inbox（收集箱）**
`内容` · `类型`（收集/问题/思考）· `标签` · `来源` · `记录日期` · `状态`（待处理/已转任务/已归档）

**review（复盘）**
`日期` · `今日完成` · `卡点困难` · `明日计划` · `一句话总结` · `周次`

**week（周计划）**
`周次` · `本周目标` · `关键结果` · `下周计划` · `周总结`

> 字段名是中文，必须原样使用。日期格式 `YYYY-MM-DDTHH:MM:SSZ`。
> 未填字段留空即可，不会报错。

### 6. 读取示例

```bash
curl "https://2566.online/workboard/api/external/v1/task?size=200" \
  -H "X-API-Key: 你的Key"
```

返回 `{"items":[...], "total":N, "page":1, ...}`，`size` 最大 500。

### 7. 权限与错误

| 现象 | 原因 |
|---|---|
| 401 | Key 无效 / 已吊销 / 未带 `X-API-Key` |
| 403 | 用的是 `read` Key 却想写入 |
| 400 | 表名不在白名单 / 字段格式错 |

### 8. 同步说明（重要）

通过外部 API 写入的记录会进同步队列，每小时由桥接器回写到 WorkBuddy 平台（本阶段双轨）。
**服务端是数据唯一落点**：无论从网页、Agent 对话还是 API 写入，都落在同一套数据库，多端看到的是同一份数据。

---

## 四、Key 的安全建议

- 一台设备/一个用途一把 Key，备注写清楚，便于单独吊销。
- Key 不要写进代码仓库、不要发在聊天里（如需发给别人，用私密渠道）。
- 怀疑泄露 → 网页「APP Key」页吊销旧 Key，生成新的。
- 需要更强控制（限流、scope 细分）时再扩展，目前 read/write 两级够用。
